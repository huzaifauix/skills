# Assess: understand the request before making anything

A good creative partner spends the first minutes understanding the job, not producing. A skill can't sense a request the way a person does, so it uses explicit checks instead. The output is **one visible line**, shown at the top, that the user can correct in a word. Never a questionnaire.

## 1. Goal and real problem

Look past the *form* of the request to the *job* it has to do:

| They asked for | The job underneath |
|---|---|
| "An infographic about sleep" | Show tired parents the three habits that fix most bad nights, in a form they'll save |
| "Make our menu descriptions less boring" | Make a hungry customer choose this dish over the one next to it |
| "Refresh the gym's welcome email" | Get new members to come back a second time in their first week |

Name the **audience**, the **goal** (what they should think, feel or do afterwards) and what **success** looks like, even if only roughly. The angle (step 4) and the recommendation both come from this.

## 2. Clarity: go, assume, or ask

Check five things: **goal, audience, starting point, output (format and size), constraints.**

| Situation | Action |
|---|---|
| All known, or easy to infer | **Go.** State your read in the Assess line. |
| A detail is missing that you can default (size, tone, platform, number of drafts) | **Assume and say so** in the Assess line: "assuming LinkedIn 1080×1350". |
| Something **critical** is missing: no subject, conflicting goals, no idea what "good" means, or a high-stakes piece with an unknown audience | **Ask first** (see below), then stop. |

**The ask test:** would the answer *substantially* change the output, and is there no sensible default? Only then ask.

**How to ask:**
- 1–3 questions in one batch;
- multiple choice where possible, with a recommended default, so the user can answer in seconds;
- if a question tool exists (a question card), use it; otherwise ask in plain text;
- never ask one question at a time over several turns.

Examples:

| Request | Do |
|---|---|
| "Repurpose this checklist post for 'How to prepare for a job interview'" + image | Go: everything needed is there |
| "Write 3 subject lines for our spring sale email" | Go: assume the brand voice from context, and say so |
| "Help our brand stand out" | Ask: which piece (logo, website, social, packaging)? Stand out to whom, and against which competitors? |
| "Design something for the launch" | Ask: what is launching, in what format, for which channel? |

## 3. Keep / Change

Every piece has dimensions. A request keeps some and changes others. Read them from the wording, and **default anything unmentioned to Keep**, because the user chose the source for a reason.

| Dimension | Example of a request that changes it |
|---|---|
| **Message** (what it says) | "Use this layout for a new topic" |
| **Format / medium** | "Turn this article into a carousel" |
| **Layout / structure** | "Design something like this reference" |
| **Audience** | "Make a beginner version", "B2B → consumers" |
| **Purpose / goal** | "Turn the case study into a sales email" |
| **Channel / platform** | "Resize for Stories", "cut 16:9 to 9:16" |
| **Length / scale** | "Shrink to a thread", "expand into an article" |
| **Style / brand** (look, tone) | "In our brand colours", "less formal" |
| **Language / locale** | "Adapt for the UK market" |
| **Freshness** (data, dates, examples) | "Update with this year's numbers" |

**Phrasing cues for the word "repurpose":** check what sits next to it.
- "Repurpose ***this design / template / layout*** for X" → keep the layout, change the message. This is **template reuse**.
- "Repurpose ***this post / article / webinar / talk*** into…" → keep the message, change the format. This is **reformat**.
- "Design X… ***reference*** attached", "something ***like this***", "***inspired by***" → keep the core idea, change the layout and message. This is **from a reference**. The verb "design" plus the word "reference" means the user expects visual freedom.
- Two cues in conflict → choose the more literal reading and offer the flip in the Assess line.

## 4. Effort level

This is separate from clarity: a clear request can still deserve deep work.

| Signal | Leans light | Leans deep |
|---|---|---|
| Size of the deliverable | A line, a caption, a headline | A campaign, a landing page, a product, a rebrand |
| Stakes | Internal, rough, "just to see" | Public, client-facing, a launch, paid media |
| Familiarity | A well-known pattern | New territory, an unusual audience |
| The user's words | "quick", "rough", "a few ideas" | "make it great", "launch", "important", "deep dive" |

| Level | Assess | Gather | Angle | Drafts | Final |
|---|---|---|---|---|---|
| **Light** | One line | Skip | Skip | Text ideas or a quick pass | Only if asked |
| **Standard** (default) | One line | 3 references, from memory is fine | 1 angle | 3 drafts at medium fidelity | Polish + check |
| **Deep** | One line + a short brief (goal, audience, success) | 5+ references, using real tools when available | 2–3 candidate angles, pick one | 3 drafts, possibly one per angle | Polish + full check |

When the signals disagree, choose **standard** and offer to go deeper.

## 5. The Assess line

Always one line (two at most), at the very top:

> **Read as:** <preset or "custom"> · **Goal:** <the job underneath> · **Keep:** … · **Change:** … · **Effort:** light/standard/deep · *Say "…" to adjust.*

The closing hint names the one or two flips most likely to matter, for example "keep layout" or "go deep". A wrong read then costs the user one word, not one round.
